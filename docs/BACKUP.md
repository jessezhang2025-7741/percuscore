# 谱库备份、恢复与验证

入口：谱库 **Reader settings → Library backup**。全部在本地运行，不需要账号或云端服务。

## 三个独立状态

- **File generated**：App 已生成临时备份，尚不能证明系统已保存。
- **System export completed**：系统文件窗口报告成功；取消不更新。请保存在 App 数据目录以外。
- **File passed restore verification**：重新选择该文件后，在空的隔离谱库中恢复、重新打开并逐项对比内容成功。

每项显示日期与文件指纹。三个记录可能属于不同文件；验证报告只关联指纹相同的生成／导出记录。
`Last successful export` 保留旧版时间显示，但旧版时间没有文件指纹，不能补作恢复验证的导出证据。
记录保存失败会明确提示，不会假装已经持久保存；原文件与当前会话中的验证结果仍可用。

## 导出与内容一致性

点击 **Export library backup**，等待准备完成，然后在系统文件窗口选择本地文件夹或外部磁盘。
得到 `.percuscorebackup` 文件。保存在 Percuscore 的 App 文件夹以外，才能在删除 App 后继续使用。

备份包括原 PDF、作品资料、收藏、最近页码、已保存笔迹、尚未确认的草稿、每页裁剪／半页分隔线／缩放位置、单页及范围书签、节目单顺序与引用、阅读设置和画笔预设。
已移出索引的孤立文件及本机验收记录不进入备份。
最近删除中的作品仍保留索引，默认进入备份并保留删除时间；生成和验证记录显示其数量及资产大小。待永久清理项目必须先完成重试，详见[存储说明](STORAGE.md)。

准备开始时先取得索引与共享读取租约。准备期间相关索引、PDF、笔迹、草稿写入暂时返回忙碌错误；结束后释放，失败也释放。
这是进程内、同一谱库路径上的保护，包括多个 LibraryDisk 实例。它不能阻止外部工具直接改文件。
备份窗口不能同时编辑谱库；若其他阅读窗口恰好保存失败，保留该窗口并在准备结束后重试。
后续编辑不会进入已生成的快照，需要重新导出。

## 验证选中的文件

点击 **Choose backup to verify**，选择实际保存的备份。App 复制该文件到自己创建的临时工作区，检查有界大小、逐文件校验和与内容有效性，再恢复到新的空库。
重新打开后比较 PDF、已保存笔迹、有效草稿、全部索引内容和引用关系。
作品、节目单和条目等 ID 可变化；比较会规范化身份，保留顺序、页码和引用关系。
不向正式谱库加入作品，也不修改所选备份。

通过后打开 **File passed restore verification → Open isolated restored library** 查看恢复结果。
这份副本可以书写、恢复草稿和翻页；这些操作只影响副本。先检查已保存笔迹，再恢复未确认草稿。
验证副本占用本机空间；**Remove verification copies…** 只删除这些副本，保留验证报告、原备份和正式谱库。

**Export backup verification report** 导出 Markdown 和 JSON，记录文件／内容指纹、设备、系统、版本、提交、生成／导出／恢复时间和人工观察。
报告不包含 PDF 或笔迹内容。自动内容通过与真实 Files／目视验收分别记录；模拟器不能通过真实设备验收。

## 标准测试库及真实 iPad 往返

1. 在正式库的备份页点击 **Prepare standard test library**。这是独立测试库，不读取或改动正式作品。
2. **Open practice scores** 检查两份四页测试谱：红蓝已保存笔迹、额外紫色草稿、不同裁剪／旋转／缩放、单页与范围书签、五项跨作品且重复引用的节目单。
3. 返回测试库的备份页，导出到 **App 数据目录以外** 的本地文件夹或外接磁盘。
4. 点击 **Choose backup to verify**，在系统文件窗口重新选择刚才保存的文件。
5. 打开隔离恢复副本，逐项目视检查笔迹颜色／位置、草稿恢复、裁剪及缩放、书签范围与节目单顺序。
6. 返回验证详情，人工填写五项结果、外部保存确认、文件位置和复现说明，再导出报告。

标准库核对表（页码从 1 开始）：

| 作品／位置 | 应看到的内容 |
|---|---|
| Colors and draft，第 1 页 | 已保存红、蓝两条笔迹；恢复草稿后增加紫色一条。裁剪比例 120%、旋转 2°，阅读缩放 175%，位置有偏移。 |
| Colors and draft，第 3 页 | 绿色笔迹；裁剪比例 135%、旋转 −1°；首次打开作品停在第 3 页。 |
| Crops and references，第 2 页 | 绿色笔迹；裁剪比例 135%、旋转 −1°，阅读缩放 200%；首次打开作品停在第 2 页。 |
| 书签 | A 的 Entry A 为第 1 页，Rehearsal passage 为第 2–4 页；B 的 Second cue 为第 3 页，Closing phrase 为第 3–4 页。 |
| Repeated references 节目单 | A 全曲 → B 第 3–4 页 → A 第 2–4 页 → B 全曲 → A 第 2–4 页。A/B 分别为上面两份作品。 |
| 自动恢复计数 | 2 作品／2 PDF、1 节目单、3 页已保存笔迹、1 页草稿。 |

首次打开的最近页码用于核对恢复位置；检查其他页面后它会随正常阅读更新。

未执行保持 Not run；失败会保留在该记录中，改成 Passed 不能抹去失败历史。修复后重新选择文件验证以建立新记录。
真实设备通过还要求：可追溯构建、相同构建／设备／系统、同一文件的系统导出记录、外部保存确认和全部目视项目通过。
切换构建、设备或系统后旧人工记录只读，需重验。自动测试不能代替真实 Files/Pencil 验收。

## 加入正式谱库

**Choose backup to restore → Restore and add to library**：

- 空库恢复作品、节目单、阅读设置和画笔预设。
- 非空库加入副本，保留当前作品和设置；重复恢复会产生重复副本。
- 新作品 ID 重新分配，书签和节目单自动连接本次恢复的作品。
- 有效草稿在相应页面提供原有的恢复提示。

## 失败与中断恢复

保留 PERCUB01 封装和原有资源上限。新清单与索引为版本 2，仍支持读取版本 1；旧 App 不能使用新索引。文件截断、损坏内容、不支持版本或超预算会被拒绝，原备份和原谱库不变。
恢复先进入 `.restore-UUID` 工作区，内容验证后写入有指纹的持久恢复意图，再安装新文件，最后原子提交索引。
整个恢复与同路径索引加载互斥，其他窗口不会把进行中的恢复当成中断。

下次加载时：索引已提交的新增作品保留；未提交且路径、大小、指纹都匹配的新增文件与临时目录可以清理。
权限不足时保留意图供下次重试。索引回退、部分 ID、损坏意图、未知临时目录、路径重定向或文件不符时保留数据并显示提示，不冒险删除。
原谱库继续可用。不要手动删除这类保留目录，先保留备份和诊断信息。

校验检测损坏，不提供密码保护或来源认证。需要足够空间容纳备份与隔离恢复副本。

## 验证记录

自动检查涵盖：合成标准库往返和重开、非空库保留内容、内容缺失／改变、文件状态绑定、写入暂停与重试、损坏／截断／版本拒绝、索引提交失败、恢复中断检查点、清理失败重试和保守保留。
中断测试重建磁盘检查点，并非声称已在真实设备上强制终止恢复进程。
当前公开快照的实际检查结果见[验证状态](VALIDATION-STATUS.md)。原开发过程中的内部日志与历史提交没有随公开快照分发；历史通过数量不作为本次公开源码的验证结果。

**真实 iPad Files 导出／恢复及目视报告：尚未执行。** 请按上述标准库步骤完成后，从 App 导出实际记录；不会由自动测试填成通过。
