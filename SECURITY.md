# Security

Only the current development branch is maintained on a best-effort basis; there is no supported-release or response-time guarantee yet.

For a vulnerability involving private data, file parsing or destructive behavior, use GitHub's private vulnerability reporting feature if available under this repository's Security tab. If unavailable, open a minimal issue asking for a private contact channel, without exploit details, personal data or affected files. Agree on a private channel before sharing sensitive details.

Do not attach personal scores, full backups, credentials or raw device logs to a public issue. A report should include the affected commit/version, impact, and a minimal original or synthetic reproduction. Preserve the original data and a verified backup when investigating persistence problems.
